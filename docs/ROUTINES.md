## Wayside チェーン価格の月次確認

### なぜ機械取得ではなく AI が見るのか

チェーンのメニューは画像PDF・JS描画・店舗別ページが多く、スクレイピングは版が変わるたびに壊れる。
壊れたときに古い値や別の商品を黙って拾うのが一番まずい（札幌市の値を「全国平均」と書いた前例がある）。
だから毎月、公式サイトを読める者が1件ずつ見て、見つからなければ止める。

### 文面（ここから下を登録する）

リポジトリ `rs250fx-prog/waysidejapan` の `src/data/food-prices.chain.json` を見直す。
訪日客向け英語サイト Wayside Japan の「日本の食の基準価格」ページに出る、大衆チェーンの公式価格の月次確認。

あなたはこのリポジトリのクローンを持つクラウド環境で動いている。

**push できるかを先に確かめる**

調べ始める前に `git push --dry-run origin main` を実行する。`403` などで失敗したら、調査をせずに「push 権限が無い」ことだけを報告して終える。実行環境は終わると破棄されるので、push できない状態で調べても結果が残らない。

**手順**

1. `src/data/food-prices.chain.json` を読む。`items` の各品目に `chains`（掲載中）と `unresolved`（前回確認できなかった社）がある。
2. `chains` の各行について、`url` の公式ページで `product` の現在の税込価格を確認する。
   `memo` に前回の取り方（店舗、PDFの版、JS描画の回避方法、要再確認の点）が書いてあるので先に読む。
3. `unresolved` の各社も毎回見に行く。公式に価格が載るようになっていれば `chains` に移す。
4. 結果を JSON に反映する（下の「書き換えの決まり」）。
5. `_checkedAt` を今日の日付（JST、YYYY-MM-DD）にする。**価格が1件も変わらなくてもここは更新してコミットする**（ページに確認日を出しているため）。
6. `npm ci && npm run check && npm run build` が通ることを確かめる。
7. `git add src/data/food-prices.chain.json` で**このファイルだけ**を add し、main にコミットして push する。`git add -A` は使わない（運営者が同じリポジトリを並行して触る）。
   コミットメッセージは `chore: チェーン価格の月次確認（YYYY-MM）`。本文に、変わった価格（旧→新）、確認できなかった行とその理由、次回への申し送りを書く。

**価格の取り方（揃える条件）**

- 税込・店内飲食・並盛（レギュラー）・東京の通常店。都心店や空港店の割増価格は使わない。地域別価格は東京（コンビニは関東）。
- 見るのは**そのチェーンの公式サイト**（公式メニュー、公式PDF、公式の店舗ページ、公式プレスリリース）だけ。グルメサイト、ブログ、検索結果の要約、記憶の数字は使わない。
- 公式の表示をそのまま入れる。丸めない（セブン-イレブンは小数で出している）。税抜しか無ければ入れずに `memo` に書く。
- 品目ごとの条件は `what` のとおり。とんかつ定食はロースかつ、すき焼きは食べ放題以外の牛すき焼き、焼肉は食べ放題コースの最安〜標準。

**書き換えの決まり**

- 価格が変わっていたら `jpy`（幅なら `jpyMax` も）と `checkedOn` を更新する。商品名が変わっていれば `product` も直す。
- 変わっていなければ `checkedOn` だけ今日にする。
- **確認できなかった行は `jpy` も `checkedOn` も触らない。** 前回値と前回の確認日がそのまま残り、ページ上で古いことが分かる。`memo` に「YYYY-MM 確認できず：理由」を足す。
- 商品が無くなった、公式から価格の掲載が消えた場合は、その行を `chains` から外して `unresolved` に理由つきで移す。**似た別の商品で代替しない。別のチェーンに差し替えない。** 差し替えは運営者が決める。
- PDFや画像の版が変わって URL が変わったら `url` を新しいものにする。
- `note` はページに英語で出る。事実が変わったときだけ直す（例：メニューの版の年月）。`memo` は内部用で日本語でよい。
- `chains` は `jpy` の安い順に並べる（`tier: "premium"` は末尾）。
- 新しいチェーンや品目は足さない。`src/data/food-prices.ts` と他のファイルは触らない。

**止める条件**

- JSON が壊れている、ビルドが通らない、push できないときは、コミットせずに状況を報告して終える。
- 半分以上の行が確認できないとき（サイト側の障害やアクセス遮断が疑われる）は、何も書き換えずに報告して終える。

**完了時の報告**

- 確認できた行数／全行数、`_checkedAt` に入れた日付
- 変わった価格の一覧（チェーン・商品・旧→新）
- 確認できなかった行とその理由、`unresolved` から `chains` に移した社、逆に外した社
- push したコミットのハッシュ
- 調査後に push が失敗した場合は、変更後の JSON の差分（変わった行すべて）を報告にそのまま貼る。実行環境は破棄されるため、報告に載せなかったものは失われる
