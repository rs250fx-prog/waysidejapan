## 1. プロジェクト概要

- **目的**：訪日外国人旅行者向けの英語（→多言語）メディアでアフィリエイト収益を得て、最終的に日本円で受け取る
- **運営者の強み**：日本在住の日本人。国内旅行・グルメ・温泉・バイクに精通しており、本州・四国・九州を全域カバーできる
- **差別化の核**：外国人ブロガーが大半の市場で、「日本人ローカル × 一次体験 × 西日本の鉄道周遊」を扱うサイトは見当たらない

## 2. コンセプト（確定）

- **仮称**：Local Line Japan（→ 2026-09-26 に **Wayside Japan / waysidejapan.com** で確定。`SPEC.md` 参照）
- **仮キャッチコピー**：Ride, Eat, Soak.
- **軸**：鉄道でめぐる旅（地域パスでの周遊）＋ 駅弁・ご当地グルメ・温泉
- **差別化用のサブカテゴリ**：バイク、温泉レビュー（既存の日本語の温泉レビュー資産を英訳して活用）
- **集客の考え方**：鉄道パスは報酬率が低い（後述）。「パスで売る」のではなく「パスで人を呼ぶ」。パス記事で集客し、沿線のツアー・eSIM・宿で収益化する

### コンテンツカテゴリ

| カテゴリ | 役割 | 内容例 |
|---|---|---|
| Rail Routes | 集客＋収益 | 地域パスの完全ガイド、モデルルート |
| Eat（駅弁・ご当地グルメ） | 集客＋収益 | ご当地グルメ、食べ歩き（ツアーへの送客） |
| Soak（温泉） | 差別化 | 駅近の温泉、日帰り入浴 |
| Konbini | 集客 | 大手コンビニで買うべき物、季節限定品、地域限定品、駅ナカ |
| Column | 専門性・独自性 | 旅 × 地方の歴史・企業・特産品の深掘り |
| Ride（バイク） | 差別化 | ツーリングルート（月2本程度） |

### コラムの方針

- 旅と絡める（例：「なぜ愛媛はみかん王国なのか」「九州の焼酎メーカー地図」「コンビニ3社はなぜ強いのか」）
- 『業界地図』などの本は、全体像をつかむための参考資料として使う
- 記事に載せる数値は、一次情報で裏付けを取る（企業IRの英語版、農林水産省・観光庁などの統計、自治体や業界団体の公表データ）。出典は必ず明記する
- **禁止事項**：本の図表や業界マップの転載・英訳、解説文の翻訳、本の構成（業界分類など）の丸写し

## 3. 初期エリア（確定）

- **軸**：瀬戸内エリアパス（JR西日本・JR四国）
  - 関西から岡山・広島・山口、四国（高松）、さらに九州（福岡・佐賀・長崎・熊本・大分）までカバーし、有効期間は7日
  - 本州・四国・九州を1本のルートでつなげられる
- 最初の3〜4か月はこのエリアに集中する。その後、九州 → 関東の順に拡張する

## 4. 収益設計（2026年9月の調査時点。登録時に最新条件を要確認）

| プログラム | 報酬 | Cookie | 備考 |
|---|---|---|---|
| GetYourGuide | 約8% | 31日 | Travelpayouts経由。ツアー・体験 |
| Viator | 約8% | 30日 | ツアー・体験 |
| Airalo（eSIM） | 12% | 30日 | 全記事に入れやすい |
| Agoda | － | － | 宿。Travelpayouts経由で支払い条件が有利 |
| Booking.com | 4% | 1セッション | 条件が厳しい |
| Klook | 2〜5%（ASPにより差あり） | 30日（ホテルは7日） | 多言語化の段階で導入。アジア圏に強い |
| JRPass.com | JR Pass 1%／地域パス 3% | 約28日 | 2023年の値上げ時に報酬率が引き下げ。集客用 |

- **ASP**：まずTravelpayouts（無料、アクセス数条件なし、100以上のブランドの報酬を1つの残高に集約）
- **受け取り**：PayPal（最低50ドル）→ 日本の銀行へ出金。銀行振込は最低400ドル
- **税務**：W-8BENを提出。海外からの報酬も日本の所得として申告する（税理士に確認）

## 6. 機能要件

### 6-1. 多言語対応（初期設計に必須）

- 最初は英語のみで公開し、後から繁体字中国語・韓国語を追加
- URLは言語ごとに分ける：`/en/`、`/zh-tw/`、`/ko/`
- hreflangタグ（x-defaultを含む）を全ページに出力
- Astroのi18n機能で構成する。UI文言は辞書ファイルで管理
- 翻訳はAIで作成し、地名・店名・料金は人の目で確認する運用

### 6-2. 為替の自動換算（独自機能）

- 日本円をもとに、USD・EURを自動換算して表示する
- 将来は多言語化に合わせてTWD・KRW・AUD・GBPに拡張できる設計にする
- 表示例：`¥1,200 (≈ $8 / €7, as of Sep 26)`
- 構成案：
  - Workers Cronで1日1回レートを取得し、KVに保存
  - 記事内の価格は部品化する（例：`<Price jpy={1200} />`）。本文に換算後の金額を直接書かない
  - 基準日を必ず表示し、「≈」で概算であることを明記する
  - 取得に失敗した場合は、前回値と基準日を表示する
- レート取得元の候補（要比較・検証）：Frankfurter（ECBのデータ、キー不要）、open.er-api.com など
  - ECBは営業日しか更新されないので、土日は直近の営業日のレートを使う
- 将来の拡張：単独ツール「旅行予算シミュレーター」にして被リンク獲得を狙う
- 注：SEOの順位に直接効く機能ではない。UXの差別化として位置づける

### 6-3. アフィリエイト部品

- ツアー、eSIM、宿のCTA部品
- リンクには`rel="sponsored nofollow"`を付ける
- 記事冒頭にアフィリエイト開示を入れる（米国FTC対応）

## 7. SEO・法務の要件（海外SEOは初めて）

- **ドメイン**：.comを推奨（.jpは「日本の人向け」と判定されやすい）
- **E-E-A-T**：著者ページで「日本在住の日本人」「実際に乗った・食べた・入った」ことを前面に出す。写真は自分で撮影したものを使う
- **AI要約への対策**：一般的な「◯選」記事は避け、一次体験（実際の写真、料金、乗り換え）と地域特化を徹底する
- **構造化データ**：Article、BreadcrumbList（必要に応じてFAQ）
- **サイトマップ・Search Console**（言語別）
- **表記**：円＋ドル・ユーロ換算、24時間表記、ヘボン式ローマ字
- **法務**：FTCの開示、EU訪問者向けのCookie同意バナー（アフィリエイトCookieのため）、プライバシーポリシー
- **Google依存を避ける**：ニュースレター登録の導線、Pinterest・Redditへの展開を想定しておく
