# 系譜の地図：ジャンルの網羅と、1系譜の深さ

**作成日**：2026-10-09（案。承認後に確定）
**位置づけ**：`CONTENT-PLAN-EAT.md` 第3節「品目と系譜の候補」を全面に広げたもの。
横（網羅性）は「日本で食べられているものを、外国人が出会う順に全部」、縦（専門性）は「1系譜につき同じ10項目を、出典つきで埋める」。

---

## 0. 読み方

- **ジャンル（13）→ 品目ハブ（約90）→ 系譜ページ（約260）** の3段。数は候補の数で、全部書く約束ではない
- 各行の ★ は優先度。★★★＝最初の6か月、★★＝1年目、★＝それ以降か、反応を見て
- 「系譜」は料理の流派だけでなく、**土地・店の型・時代**も含む。博多ラーメンは土地、立ち食いそばは店の型、洋食は時代の系譜
- 出典の軸：農林水産省「うちの郷土料理」（都道府県別・1,300品超、歴史と材料が公的に書いてある）、自治体・観光連盟、業界団体（全国製麺協同組合連合会、日本蒲鉾協会 など）、博物館（新横浜ラーメン博物館、カップヌードルミュージアム、味の素食の文化センター）、JAS・景品表示法などの**表示の規則**（和牛、地鶏、本みりん、純米）

## 1. 1系譜の深さ（固定10項目）

系譜ページはこの10項目を必ず同じ順で持つ。項目が揃っているから横に比べられる。

| # | 項目 | 書くこと | 根拠 |
|---|---|---|---|
| 1 | 起源 | いつ・どこで・誰が・なぜ。複数説は併記。年号に出典 | 出典 |
| 2 | 定義する要素 | 何がそれをそれにしているか（スープ／麺／だし／切り方／焼き方／器） | 出典＋実見 |
| 3 | 土地との関係 | なぜその土地か。港・産業・気候・人の移動（引揚げ、炭鉱、港湾労働） | 出典 |
| 4 | 店の型と値段 | 屋台／大衆店／専門店／高級店。基準価格ページの行と、本場の実勢 | 価格データ＋実見 |
| 5 | 注文と食べ方の仕組み | 食券、替え玉、硬さ指定、つゆの付け方、相席。日本人がどうしているか | 実見 |
| 6 | 地域差・派生 | 同じ名前で何が違うか。「正解が一つでない」ところ | 出典 |
| 7 | 本場で食べる・行き方 | 街、駅、時間帯、最寄りの柱ルート、近くの湯 | 公式時刻・運賃 |
| 8 | 誤解 | 外国人が思い込みがちなこと。「伝統食だと思っていた」「生卵は危ない」 | 出典 |
| 9 | 本場と出先の違い | 東京・大阪で「〇〇ラーメン」として出るものは本場と何が違うか。チェーンの均一化、麺の製造地、表示の基準、値段。日本人でも分かっていない人が多い（2026-10-10 追加） | 出典＋実見 |
| 10 | 出典 | 2本以上。公的・一次を優先 | — |

品目ハブは、この9項目のうち 1・2・4・6 を系譜ごとに**横並びの表**にし、残りを系譜ページに送る。

## 4. 横に比べるための共通データ

系譜の表を記事ごとに手で書くと、項目がばらけて比べられなくなる。**系譜は1か所のデータに持ち、ハブと系譜ページの両方がそこから描く**。

```
src/data/lineages/ramen.json
{
  "dish": "ramen",                  ← 基準価格ページの chainKey / 品目と一致
  "axes": ["soup", "noodle", "topping", "howToEat"],   ← この品目の比較軸
  "lineages": [
    { "key": "hakata", "name": "Hakata", "nameJa": "博多ラーメン",
      "origin": { "place": "福岡市", "era": "1940s", "sources": [...] },
      "soup": "...", "noodle": "...", "topping": "...", "howToEat": "替え玉・硬さ指定",
      "where": ["福岡"], "route": "K12", "status": "published" }
  ]
}
```

- 価格ページの品目名 → ハブへのリンクは、この JSON にハブがある品目だけに出す（404 を構造で防ぐ）
- 系譜の `status` が `planned` のものは、ハブの表に名前だけ出して「準備中」にする。空のリンクを作らない
- 入稿フォームの「品目ハブ／系譜」タブは、この JSON を書く入口にする
