### このサイトの軸（判断の前提）

**2本立ての根拠。** 記事は `basis: visited`（自分で行った。`experience` 必須、緑の確認日バッジ）と
`basis: researched`（調べて書いた。出典2本以上、灰色の `Researched · N sources`、本文前に
「行っていない」と明示）に分かれる。混ぜると読者が根拠の強さを見分けられなくなる。
量産は `researched` が主軸。`<FromExperience>` で調査記事の中に実見を日付つきで差し込める。

**基準価格。** 「日本人なら普通いくら払うか」を数字で出すのがサイトの看板。
`/en/food-prices/`（68品目）がその集約点で、全ページのヘッダー・フッタ・`<RateNote>` から常時リンク。
公的統計（小売物価統計・特別区部）と運営者の実見を並べ、食い違うときは両方出す。
ラーメンは統計620円／実勢1,000円、牛丼チェーンは統計489円／実勢490円。

**通貨はユーロが先**（`¥22,000 (≈ €137 / $148)`）。欧州圏が主要層。
中国語は扱わない。韓国語は最後の候補。

**扱う地域は地方が主体、関東は強みとして使う。** 関東が最も土地勘があるが競合も最多。
英語で欠けているのは地方のほう。

### 動いている自動処理

- `.github/workflows/rates.yml` — 為替を日次取得。0.3%未満の変動では何もしない
- `.github/workflows/food-prices.yml` — 小売物価統計を月次取得（毎月27日）。
  `ESTAT_APP_ID` は GitHub Secrets にある。**値が変わらなければコミットしない**
  （Pages のビルドは月500回・アカウント共有枠のため）

### 入稿

`/admin`（Cloudflare Access の内側）→ D1 → `GET /api/intake/:id` を AI が読んで MDX にする。
ガイド記事とコラムの2タブ。保存時に弾く条件がある（体験か実測のどちらか必須、
金額に ¥ や円を混ぜない、証拠の無い数値、column は出典必須、料金確認日）。
`/api/health` で配線、`/build.json` で反映中のビルドを外から確認できる。

### 気をつけること（このプロジェクトで実際に起きた失敗）

- **デモで書いた記事に事実誤りがあった。** 「のぞみに乗れない」「フェリー対象外」は
  どちらも誤りで、JR西日本の公式と突き合わせて判明した。`basis: visited` の記事でも、
  パスの条件のような外部仕様は出典を持たせる
- **自動取得が札幌市の年平均を「全国平均」として書き込んだ。** 地域が見つからないとき
  勝手に代替していたのが原因。**見つからなければ止める**ように直した。
  見た目では気づけない種類の誤りなので、黙って代替しない
- **小売物価統計の API に外食品目の全国平均は無い**（都市別のみ）。
  ネットの「全国平均」は各サイトの独自計算。だから特別区部を使い、そう名乗っている

## 補足：このチャットで決めたこと

| 決定 | 理由 |
|---|---|
| ドメイン `waysidejapan.com` | wayside＝線路沿い。鉄道軸と `Ride, Eat, Soak.` に噛み合う |
| URL にカテゴリを含める | パンくずと構造化データが一致する。移動不可を受け入れる |
| 為替はビルド時に焼き込む | 静的生成なので KV に入れても HTML は変わらない |
| 計測は GA4 | 記事×プログラム×配置の外部クリックが中心KPI。CWA では取れない |
| Astro 7 | 着手時に25ファイルだったので、2メジャー遅れで始める理由が無かった |
| 配色は Persimmon（柿） | CTA の視認性。文字 `#a8441f` と塗り `#c0532b` を分ける |
| 画像は 3:2 基本・`aspect-ratio` | カメラ出力が 3:2。高さ固定だと SP で潰れる |
| 量産は AI 執筆＋人の確認 | 収益までの距離を詰める。ただし `basis` で体験記事と分ける |
| 日数は 16/12/10 | 仏16.5泊・独15.2泊／英12.8・豪13.2／米10.7 に対応 |
| 入口は4空港 | 関西26.9%・成田30.2%・福岡7.2%・中部5.4%。中部は独立（四国とは繋がらない） |
