### なぜ食か

- 基準価格ページ（68品目・チェーン98価格・公的統計）は英語圏に同じものが無い。**差別化の核はすでに食にある**
- 運営者の強みと一致する（秘境宿からミシュランまで、ローカルガイド Level 8）。本人が自信を持てる領域のほうが量産が続く
- 訪日前の期待は「日本食を食べること」が毎年1位。最も満足した飲食は 肉 32.5%／ラーメン 19.7%／寿司 13.7%（`CONTENT-PLAN.md` 第0節）
- 英語で欠けているのは地方の食。鉄道はそこへ行く手段として自然に残る

### 「正しい食文化」の書き方

英語で "the correct way" と書くと説教になる。**「正しい」は「仕組みと理由」に翻訳する。**

- ×「お通しは断ってはいけない」
- ○「お通しは席料。300円なら良心的、1,000円なら観光客向けの店。それで店を見分ける」

「なぜそうなっているか」「日本人はどう振る舞っているか」「それがいくらか」を書けば、結果として正しい振る舞いが伝わり、しかも検証できる。
**正しさが一つでないもの**（だしの東西、モーニングの東西差、ラーメンの系譜そのもの）は、割れていると書く。一つに決めると嘘になる。

## 2. 記事の4層

```
品目ハブ（Dish）            /en/eat/ramen/
 ├ 系譜・土地（Lineage）     /en/eat/ramen-hakata/  /en/eat/ramen-kitakata/  /en/eat/ramen-iekei/
 │   └ 旅（Route）           /en/rail/...  既存のモデルルートと区間記事に接続
 └ 仕組み・誤解（Column）    /en/column/lunch-and-dinner-are-different-products/
```

### 層1：品目ハブ（1品目1ページ）

その品目について英語で最初に読むべき1ページ。**基準価格ページの行と双方向にリンクする**（価格ページの品目名 → ハブ、ハブの値段欄 → 価格ページ）。

構成（固定）：

1. **What it is** — 何か。日本人にとっての位置づけ（日常食か、ハレの食か）
2. **Why it is the way it is** — 仕組みと理由。食券機、替え玉、昼夜差、時価
3. **What it costs** — 統計・チェーン・実勢・観光地価格。価格ページのデータをそのまま出す（手で書き写さない）
4. **The lineages** — 系譜の地図。起源の土地・年代・何が違うか（スープ、麺、具、食べ方）を**同じ項目で横に並べる**
5. **Where to eat it, and how to get there** — 系譜ごとの本場の街と、そこへの移動（旅の層へのリンク）
6. **What people get wrong** — よくある誤解
7. **Sources** — 出典

根拠：`basis: researched` を基本とし、出典2本以上（農水省「うちの郷土料理」、自治体、業界団体、博物館、書籍）。**運営者が食べた系譜は `<FromExperience>` で日付つきで差し込む。** 歴史の記述は出典の無い断定をしない（起源が複数説あるものは併記）。

### 層2：系譜・土地

1系譜1ページ。「博多ラーメンとは何か、なぜそうなったか、本場で食べるには」。

1. 歴史と起源（屋台、港、産業との関係）。年号と出典つき
2. 何が違うか（ハブの横並び表の、この系譜の行を詳しく）
3. 本場で食べる：街、店の種類（屋台・老舗・チェーン）、時間帯、値段、注文の仕組み
4. **行き方**：最寄りの柱ルート（W/K/E/C）と区間記事へ。空港からの所要と運賃
5. 近くの湯（あれば1〜2軒。温泉はここに住む）
6. 出典

根拠：`researched` から始め、行ったら `visited` に昇格。**層2が旅の収益（宿・eSIM・フードツアー）に最も近い。**

### 層3：旅

既存のモデルルート（`CONTENT-PLAN.md` 第2節）と区間記事。**各日に「その日の食の目的地」を1つ置く**設計に改める。
ルートの価値は「速く安く」ではなく「何を食べに降りるか」。

### 層4：仕組み・誤解（コラム）

既存のコラム枠。1本1テーマ。出典必須は変えない。

## 5. 入稿フォームに足すもの

- **記事型**：ガイド／コラム／モデルルート／**品目ハブ**／**系譜**
- 品目ハブ：`dish`（価格ページのキーと一致させる）、系譜の表（名前・土地・起源年代・スープや生地など比較軸・一言）
- 系譜：`dish`、`lineage`、本場の街、最寄りの柱ルート、近くの湯
- 保存時に弾く条件を足す：歴史の年号に出典が無い、系譜の比較軸が揃っていない
