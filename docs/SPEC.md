## 1. 媒体の位置づけ

| 項目 | 内容 |
|---|---|
| 媒体名 | Wayside Japan |
| タグライン | Ride, Eat, Soak. |
| 言語 | 英語のみ。**中国語は扱わない**。韓国語は最後の候補（T-16） |
| 目的 | **アフィリエイト収益**。日本円で受け取る |
| 読者 | 訪日を計画中／滞在中の外国人旅行者。**英語圏と欧州圏が主要層**。韓国は将来 |
| 初期エリア | 瀬戸内（関西〜岡山・広島・山口〜四国〜九州北部）。その後 九州 → 関東 |
| 更新頻度 | 週2〜3本（3か月で30本） |

名前は wayside（線路沿い・道端）から採っている。**幹線を速く移動するのではなく、沿線で降りて食べて浸かる**という編集方針がそのまま名前になっている。ここが「速く安く移動する」型の競合との分かれ目であり、記事構成の前提でもある。

### 扱う地域（2026-09-27 決定）

運営者の土地勘は **関東 > 東北 ≒ 東海（岐阜まで）・中部・北陸 > 関西 > 中国 > 四国 > 九州** の順（`src/data/regions.ts`）。在住も東京。

**それでもサイトの主体は地方に置く。** 関東は最も強いが、英語圏向けには既に書き尽くされている。英語で欠けているのは、1週間がパス1枚で組み立つのに誰も書いていない地域のほう。関東は主題にせず、必要なところで強みとして使う。

`src/data/areas.ts`（サイトが扱う場所・運用の状態）と `src/data/regions.ts`（運営者が詳しい場所・強い順）は別物。更新のタイミングが違うので混ぜない。

### 差別化の核

「日本人ローカル × 一次体験 × 西日本の鉄道周遊」。外国人ブロガーが大半の市場で、この3つが揃うサイトが見当たらない。**実際に乗った・食べた・入ったことの証跡**（自前写真、確認日付きの料金、乗り換えの実態）を構造として持たせる。

### 収益の考え方

鉄道パスの報酬率は低い（JR Pass 1%／地域パス 3%）。**パスで売るのではなく、パスで人を呼ぶ。** パス記事で集客し、沿線のツアー（約8%）・eSIM（12%）・宿で収益化する。したがってパス記事は「報酬の低い記事」ではなく**入口**として設計し、エリアハブ経由で収益記事へ送る内部リンクを構造で担保する。

  { key: 'soak', enabled: true  },

## 6. i18n と URL 設計

### ロケールの持ち方

**ディレクトリで分ける**（`src/content/en/rail/...`）。frontmatter に `locale` を持たせる方式は採らない。

理由：未翻訳の記事が「存在しない」状態になるため、hreflang を**実在するページだけ**に出す実装が自然に書ける。`locale` フィールド方式だと、翻訳のないページにも hreflang が張られて相互参照が壊れる（Google が無視する典型）。

言語間の対応付けは **`translationKey`（原文のslug）を全記事に必須**で持たせて行う。

### URL

| 種類 | URL |
|---|---|
| トップ | `/en/` |
| 記事 | `/en/rail/setouchi-area-pass/` |
| カテゴリ | `/en/rail/` |
| エリアハブ | `/en/areas/setouchi/` |
| 著者 | `/en/about/` |
| 開示 | `/en/disclosure/` |
| プライバシー | `/en/privacy/` |

- Astro i18n、`prefixDefaultLocale: true`。**英語も `/en/` に入れる**
- `/` → `/en/` は **`_redirects` で 301**。後から言語を足しても設計が変わらない
- **カテゴリをURLに含める。** パンくずと `BreadcrumbList` が一致し、トピッククラスタが構造で見える。代償は**後からカテゴリを移せないこと**。移動したくなったら301を張る前提で、カテゴリの粒度は最初に決め切る
- 日付はURLに入れない（常緑コンテンツのため）

### hreflang

`en` / `zh-TW` / `ko` と **`x-default` は `/en/`**。出すのは実在ページのみ。

### 翻訳の運用

AI翻訳 → **固有名詞・料金・乗り換えを人間が確認**。これを構造で守るため、frontmatter に `translationStatus: machine | reviewed` を置き、**`machine` のあいだは `noindex`**。品質が未確認の言語版が先にインデックスされるのを防ぐ。

## 8. 為替の自動換算

### 方式：ビルド時に焼き込む

**静的生成なので、KV に新しいレートが入ってもビルド済みHTMLの数字は変わらない。** KV を活かすにはクライアント側で差し替えるしかなく、初期表示のちらつき・JS無効時の欠落・クローラに数字が見えないという代償を払う。「≈」の概算表示に日次以上の鮮度は要らないので、**ビルド時に焼き込む**。

```
GitHub Actions（cron・毎日）
  → Frankfurter（ECB、キー不要）からレート取得
  → src/data/rates.json と比較
  → 変動が 0.3% 未満なら何もしない        ← ビルド回数を節約
  → 0.3% 以上なら rates.json をコミット
  → そのコミットが Pages のビルドを起こす
```

Deploy Hook も Worker も KV も使わない。`rates.json` がリポジトリに残るので、**ビルドの再現性が保たれ、ネットワークに依存せずビルドできる**。

- 取得失敗時は**コミット済みの前回値を使い、ビルドを落とさない**（体裁の問題で公開が止まるほうが損失が大きい）
- ECB は営業日しか更新されない。土日は直近営業日のレートを使い、**その日付を表示する**
- 通貨は **EUR → USD の順で表示する**（`DISPLAY_CURRENCIES` の並び順が表示順）。欧州圏を主要層に置く決定による。
  中国語圏は扱わないので TWD は持たない。韓国語に着手する段で KRW を足す
- 基準日の注記には**ユーロとドルの両方のレート**を出し、出所（ECB・営業日のみ更新）も書く

### 表示

- `<Price jpy={1200} />` → `¥1,200 (≈ $8 / €7)`
- **基準日は各金額に付けない。** 記事フッタで `<RateNote />` が1回だけ出す
  → `Prices are in Japanese yen. Conversions are approximate, at ¥xxx/$1 as of Sep 26, 2026. Fares verified: Aug 2026.`
- 丸めは USD/EUR 整数、1未満のみ小数1桁
- **本文に換算後の金額を直接書かない。** 検査スクリプトで `$` の直書きを弾く

**The Invisible Tourist**（「10 Day Shikoku Itinerary」6,825語、記事内画像32枚）— 信頼に最適化

- バイラインが **`Alyse • 12+ Years Travelling Japan`**。名前の隣に資格情報
- **開示が最初のリンクより前**

- ただし **H1 → H3 で見出し階層が飛んでいる**
- **価格の記載がゼロ**（`¥` が1回も出ない）

**空いている場所**

5. **実用と信頼が分断されている。** Cheapo は価格が濃く人格が薄い、Invisible は逆。**両方やるサイトが無い**

### 画像の比率とサイズ（`src/lib/images.ts`）

**SP を基準に決めて PC に広げる。** 390px 幅 × DPR3 = 実質 1170px 必要で、PC のカード（3列・400px 程度）より要求が大きい。

| 用途 | 比率 | 根拠 |
|---|---|---|
| ヒーロー | 3:2 | カメラの出力が 3:2。トリミングの判断が要らない |
| 全幅の帯 | PC 21:9 / **SP 3:2** | 同じ比率だと SP で細すぎて何も写らない |
| カード | 3:2 | カテゴリ入口・関連記事 |
| 一覧サムネ | 4:3 | 小さいので面積効率。3:2 は被写体が判別できない |
| 著者写真 | 4:5 | 人物は縦 |
| 本文中 | 3:2 | 本文幅 880px に合わせる |

**高さを px で固定しない。`aspect-ratio` で持つ。** SP で幅いっぱいになったとき、固定高さだと被写体が潰れる。`width`/`height` は必ず出力して CLS を防ぐ。ヒーロー以外は lazy。入稿する写真は**最低 2000px 幅**。

### 書体

- 欧文：可変フォント1ファイルを**自己ホスト**（`preload` + `font-display: swap`）
- 日本語：駅名・店名の数文字のみなのでシステムフォント
- **使うフォントに実在するウェイトだけを指定する**（存在しないウェイトを指定すると和欧でずれる）

### 配色（確定・案4 Persimmon）

5案を同一部品で比較して決定（2026-09-26）。**アクセントは暖色（柿）。CTAの視認性を最優先した。**

| トークン | 値 | 用途 |
|---|---|---|
| `--bg` | `#faf7f0` | 地 |
| `--surface` | `#fffefa` | 浮かせる面（カード・パネル） |
| `--surface-2` | `#f2ebdd` | 沈める面（注記・フィルタ帯） |
| `--ink` | `#17161a` | 本文・見出し |
| `--ink-2` | `#3d382f` | 副文 |
| `--ink-3` | `#2b2720` | 長文本文 |
| `--muted` | `#6d665a` | メタ情報 |
| `--muted-2` | `#5e574b` | 注記・警告語 |
| `--line` | `#e3dccc` | 細罫 |
| `--line-2` | `#eee7da` | 極細罫 |
| `--accent` | `#a8441f` | **文字・リンク・見出しラベル** |
| `--accent-fill` | `#c0532b` | **塗り（ボタン背景）専用** |
| `--confirm` | `#2f5d47` | 確認済みの符号（`Fares verified` バッジ、`Buy it if`） |
| `--placeholder` | `#efe6d6` / `#ded3bf` | 写真プレースホルダ（実装時は不要） |

**アクセントは文字用と塗り用を分ける。** 明るい `#c0532b` は小さい文字でコントラストが足りない（本文背景比 4.9:1 未満）。文字は必ず `#a8441f`（6.0:1）を使う。

**緑 `#2f5d47` は「確認済み・肯定」の符号として予約する。** `Fares verified` バッジと `Buy it if` 以外に使わない。**警告（`Skip it if` 等）に別の暖色を当てない**。アクセントと混ざって意味が読めなくなるため、警告は `--muted-2` の地の文字色で書き、語そのもので意味を持たせる。

明度は `--bg` / `--surface` / `--ink` の3つだけで動く構造にする。後から「明るすぎる」となっても1か所で直る。

ダークモードを入れる場合は**アクセントを別トークンで持つ**（`#a8441f` はダーク背景で 2.1:1 になり読めない）。初期は実装しない。

**モック一式（全14面）**：Artifact キャンバス `https://claude.ai/artifact/4RtUPohMiyQ28xoAAdQ3EQ`

### スマホ（390px）

**未決**：追従バーは開示より先に目に入る。バー内に小さく `ad` 表示を入れるか、結論ボックス通過後に出すか。後者を推奨（実装は一段複雑）。

### コラムの扱い

**コラムだけは一次体験ではなく出典で立つ。** 他の記事が「自分で行った」で成立しているのに、行っていない場所の記事が同じ体裁で並ぶと、根拠の強さが見分けられなくなる。そのため構造で分ける。

- サイドレールなし・中央寄せ・タイトル中央揃え（ガイド記事と一目で違う）
- `sources` 必須。`Sourced · N references` バッジを著者行に出す
- TOP では全幅の帯で扱い、カードに `N sources` / `Researched` を出す
- 扱う題材：地元が避ける場所、日本人でも習わなかった当たり前の知識、地方の産業や歴史

**実在の店舗・市場を名指しで批判する記事は、書き方を決めてから書く。** 「観光客を鴨にする」ではなく「同じ品が近隣より◯割高い、◯月時点で確認」という価格比較の形にする。主張が検証可能になり、読者にとっても実用的になる。出典と確認日が要るので、入稿フォーマットから起こす。

## 11. SEO・法務

### 全ページ共通（`Seo.astro` に集約）

- `title`（`ページ名 | Wayside Japan` に自動整形）
- `description`（**英語120〜160字**、全ページ個別）
- `canonical`、hreflang、OG / Twitter カード（**OG画像を実在させる**）
- `lang` 属性はロケールに追従
- **JSON-LD は `@graph` 1本**：`WebSite` + `Organization` + `Person` を全ページ、下層に `BreadcrumbList`、記事に `Article`、FAQ があれば `FAQPage`

### ページ側

- H1は1ページ1個
- **見出しレベルを飛ばさない。** 見た目だけのラベルも含め、全ページの `hN` 順をダンプして機械確認する
- 404 は `IS_PUBLIC` と無関係に**恒久 noindex**
- サイトマップは言語別。Search Console も言語別に登録

### AI要約への対策

一般的な「◯選」記事を書かない。**一次体験（自前写真・確認日付きの料金・実際の乗り換え）と地域特化**に寄せる。`pricesCheckedOn` の表示はこの文脈でも効く。

### 法務

| 項目 | 方針 |
|---|---|
| FTC開示 | 本文冒頭・最初のリンクより前。レイアウトが自動挿入 |
| Cookie同意 | **EU・英国の読者を想定するため必要。** 同意前に GA4 を動かさない（Consent Mode v2） |
| プライバシーポリシー | 取得する情報・利用目的・Cookie・**外国にある第三者への提供**（Cloudflare / Google を使う時点で該当）・開示請求・免責・改定履歴 |
| 記述と実態の連動 | `GA4_MEASUREMENT_ID` が空なら、計測タグもポリシーの該当節も出ない |

適法性の最終判断は専門家に仰ぐ。特に EU 向けの同意の粒度は要確認。

## 12. 計測

**GA4 を採用する。** Cloudflare Web Analytics のみという当初案は撤回した。

理由：本サイトの中心KPIはPVではなく**「どの記事の・どのプログラムの・どの位置のCTAが外部クリックを生んだか」**であり、CWA では取れない。Travelpayouts 側の管理画面も、サイト内のどこで発生したかまでは分からない。これが見えないと改善のループが回らない。また**国別の訪問者比率**が多言語化（T-16）の着手判断に直結する。

- `<Cta>` から `affiliate_click` を送出。パラメータに記事slug・プログラム名・本文中の位置・ロケール
- 同意前は計測しない（Consent Mode v2）
- Cloudflare Web Analytics は**最初の3か月だけ併走**（同意を拒否した読者のPVを拾える唯一の手段）。その後どちらかに寄せる
- Search Console は言語別に登録

## 13. 公開制御と検査

```ts
export const IS_PUBLIC = false;
```

`false` のあいだは全ページ `noindex`、サイトマップと RSS を出力しない。`public/_headers` の `X-Robots-Tag` と**必ずセットで**扱う。片方だけだと Search Console がエラーを出す。

### 検査スクリプト（`tools/check-*.mjs`）

実際に踏んだ失敗だけを項目にする。想像で作らない。初期に入れるのは、**他案件で実際に踏んだもの**に限る。

| 検査 | 落とす条件 |
|---|---|
| `pricesCheckedOn` | 6か月を超えた記事がある |
| 見出し階層 | 全ページの `hN` に連番飛びがある |
| description | 未記入、または重複、または英語で160字超 |
| OG画像 | 参照先のファイルが存在しない |
| 為替の直書き | 本文に `$` の金額が直接書かれている（`<Price>` を使っていない） |
| 出典 | `column` で `sources` が空、または素のURL |
| hreflang | 相互参照が片側しかない |

**わざと壊した入力で落ちることを確認してから採用する。** 通るだけの検査は意味が無い。
